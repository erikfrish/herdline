Herdline 0.6.59 (experimental) — Close in the Tabs sheet works on the first tap after an upward swipe beside the drag handle

- Tabs: after an upward swipe on the strip beside the Tabs sheet's drag handle, Close no longer needs a second tap. The drag handle no longer shows its tooltip on a long press. Code only, not unit tested. Not device-verified.
- Chat: after Insert without Enter or Append, the "Herdr took it for …" notice names the tab as it was when you tapped, also after that pane closes or the app restarts, instead of falling back to "Pane". A tab renamed after the tap keeps the name it had at the tap. Code and unit tested only, not device-verified.
- Chat: in the + menu, when Insert without Enter is greyed out because the desktop is on another tab, its second line says so ("Off: the desktop isn't on this tab") in place of its help. Insert stays off, and the desktop is not moved. This applies to OMP, pi and Claude Code panes. Code only, not unit tested. Not device-verified.
- Chat: while you read another tab than the one your draft belongs to, Chat no longer shows the draft's tab's agent server line, such as that its agent server isn't running, nor that tab's queue or withdraw note, so they are not read as the state of the tab on screen. Open, on the "Draft for …" notice, shows them on the draft's tab. Code only, not unit tested. Not device-verified.
- Chat: after Insert without Enter or Append, the notice no longer says "Inserted into": Herdr's answer shows only that Herdr took the text, not that it reached the agent's input box. The notice says Herdr took it for the tab, that it is not confirmed in the pane, and asks you to check the terminal; Check opens Terminal on that pane. Reuse text brings the text back for 60 seconds from Herdr's answer, also after you leave and come back or restart the app. Nothing is resent, and nothing holds the composer. Send is unchanged: it still says "Sent to" only once the agent confirms it. Code and unit tested only, not device-verified.
- Tabs: the 0.6.56 note that after Close the Tabs sheet no longer leaves an invisible layer that swallows the next tap was not true: the 0.6.56 change did not fix it. In 0.6.57, after an upward swipe in the Tabs sheet, Close works on the first tap, and a sheet that ends up hidden after a rotation is now removed. Partly device-verified (QA, emulator, stock Herdr 0.9.5, on 0.6.57): in Two columns and List, Close worked on the first tap after an upward swipe on the header, the drag handle or the tabs, and after dragging the sheet down and flicking it back up; in Workspace rails, after an upward swipe on the tabs; after a rotation in Two columns, no invisible layer was left. In Two columns, an upward swipe that starts beside the drag handle still needed a second tap on Close; the first line of this release covers it, not yet device-verified. Not unit tested.
- Accessibility: when the desktop's tab has the same name as the tab you are reading, TalkBack's session header no longer says that name twice. It says the desktop is on another pane of this tab, or gives the desktop tab's place, such as "tab 5 of 6", or names the desktop's workspace when it is another one. When that other workspace has the same name as yours, or neither has a readable name, it gives the workspace's place instead, such as "in workspace 2 of 2". Names that differ, even only in case, are read as before. Code and unit tested only, not device-verified.
- Tabs: a tab that changed since you last looked at it now also carries the tab strip's unread dot on its status icon in the Tabs sheet, in List, Two columns and Workspace rails, and on the side panel on wide screens; TalkBack says "changed" first for that row. When such a tab's status becomes unknown, for example because its agent exited, its card in Two columns and Workspace rails and its tab in the tab strip still show the dot, alone in place of the status icon. Pane rows are not marked, and the tab strip is otherwise unchanged. Code and unit tested only, not device-verified.
- Tabs: the tab marks redraw less often: while a terminal is updating, the Tabs sheet and the side panel can skip redrawing them when no mark changed. Code and unit tested only, not device-verified.
- Node editor and Keys: the bottom bar now has a solid surface with a thin line along its top, filling down under the navigation bar, so a form or list scrolled under it no longer shows through the reason Save is off or around the Add key button. Device-verified (QA, emulator, stock Herdr 0.9.5): the node editor in light and dark themes, in portrait and landscape, at normal and large font sizes, and Keys in landscape. A Keys list long enough to scroll under the bar in portrait was not observable.
- Node editor: there is one Save, in the top bar, where the keyboard never covers it; the second Save at the bottom is removed. While Save is off, the reason it is off stays shown above the navigation bar, and TalkBack still reads that reason on Save. A form ready to save has no bottom bar, so the form gets that space back. Device-verified (QA, emulator, stock Herdr 0.9.5): one Save, reachable with the keyboard up, when adding and editing, in portrait and landscape, at normal and large font sizes; the reason shown above the navigation bar while Save is off; no bottom bar on a form ready to save. That TalkBack reads the reason on Save was not observable. The instrumented UI test that counts the Save buttons is written but was not run.
- Chat: when Chat can't use the agent's endpoint, it says so once, not twice: when the pane's agent server isn't running, also before you press Send, and when a Send is refused for any other failed check. For a missing server, the words that say nothing was sent stay; for any other failed check, the words that name the check stay. Partly device-verified (QA, emulator, stock Herdr 0.9.5), with Kilo whose server was gone: one notice before Send and one after a Send, nothing sent, the draft kept. Any other failed check is code and unit tested only.
- Code: comments in the Gemini code now cite the Gemini 0.68.0 bundle files that its launcher actually loads. Comments only, no behaviour change.
- Chat: Gemini subagents show in Chat. A running subagent now shows while it runs, from its own record, with its task and its current step; when it finishes or is cancelled, its row updates to its state (completed, failed or cancelled) and its report, or its error. A running subagent's row is named by the subagent's id, because Gemini's record of it doesn't hold its name. At most the newest 8 running subagents show. After a Gemini crash, a subagent can show as running until the next message. Code and unit tested only, not device-verified. Reading Gemini's subagent records was host runtime-checked by the developer with Gemini 0.68.0 and a test model provider, including a cancel with Esc and two subagents running in parallel.
- Chat: Stop now works for Gemini 0.68.0. It presses Esc only while Gemini's own working timer stands over its empty input box, with no shell holding focus and nothing waiting in its queue; the stop is not confirmed from Gemini's history. Send, attachments, steers, queueing and questions stay off for Gemini, and its agent card says why. Code and unit tested only, not device-verified. That Gemini 0.68.0 cancels a working turn on Esc was host runtime-checked by the developer, in stock Herdr 0.9.5 with a test model provider.
- Chat: under Chat, Herdline reports the pane size to Herdr once per visit, from the space under Chat's header, counted in the terminal's own font, and only once it knows the session is showing Chat, so a cold launch onto Chat no longer sends a Terminal size first. The keyboard and the composer moving in Chat still never resize the pane; Terminal is unchanged. Device-verified (QA, emulator, stock Herdr 0.9.5), with OMP: a cold launch onto Chat, Chat and Terminal back and forth, the keyboard and a grown composer, and another tab and back all left the pane at Chat's size, with no Terminal size first.
- Chat: with OpenCode and Kilo, the pane's own server is checked again, still running and still in the pane, just before any request that changes something; otherwise nothing is sent. The pane report Herdline trusts must also name this pane. Code and unit tested only, not device-verified.
- Chat header: when the desktop is on another pane, the second line shows a monitor icon with the desktop's tab name, in place of "Desktop: …". The name is shortened to at least four characters with an ellipsis, or left out, and never cut to a fragment; the workspace name follows the same rule. The tab position, such as 2/5, keeps priority over the workspace name. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Chat header: a small gap, never a separator dot, sets the monitor icon apart from what comes before it, and the second line keeps the height of one text line. Partly device-verified (QA, emulator, stock Herdr 0.9.5): the gap, and the header height with the tab position beside the icon, in English and Chinese at normal and large font sizes. The second line with only the icon left on it is code only, not unit tested.
- Terminal: key labels are drawn in the same line height they are measured with, so at the Compact density and large font sizes tall glyphs such as | and the g in PgUp or PgDn are no longer cut at the bottom. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Accessibility: when the desktop is on another pane, TalkBack reads the session header with the tab you are reading and the desktop's tab, named as the visible header shows them; the visible note shows the desktop's tab name beside a monitor icon. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Accessibility: the button that moves a custom key in Settings says it moves the key one place earlier, in English and Chinese, instead of "left". In Chinese, TalkBack joins the session header's sentences with a Chinese full stop. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Chat: the composer names where it sends by the tab, as the header does, for every agent: in its To line, placeholder, hints and notices. When a pane in another tab has the same name, the placeholder, hints and notices say workspace › tab; the To line, which already ends with the workspace, adds the pane after the tab when the other tab is in the same workspace. Partly device-verified (QA, emulator, stock Herdr 0.9.5): the To line and the placeholder, with OMP and Claude Code; and, with two OMP tabs of the same name in one workspace, the placeholder, the To line and the "Sent to" notice, with one Send landing once, on the selected pane only. The hints and the other notices in that case are code and unit tested only.
- Terminal: extra keys whose cap shows only a symbol (arrows, Enter, Backspace) are read by TalkBack with a name in English or Chinese, and the custom-keys rows in Settings read the same name. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Terminal: the extra keys are laid out in whole pixels, so the last key in a row is no longer cut at the screen edge. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Chat: Send refusals and notices no longer name OMP when another agent is in the pane. They say "the agent" or describe what the agent must support instead, for example for attachments, steers and forms. Partly device-verified (QA, emulator, stock Herdr 0.9.5): with Claude Code, the "Can't read the input box" refusal, and the notice shown when the input box already has text, in English and Chinese. The attachment, steer and form wording is code and unit tested only.
- Tabs: when you choose a tab, pane or workspace, whether the desktop moves is decided from the Chat or Terminal modes as they are at that moment, including a mode you have just changed. Partly device-verified (QA, emulator, stock Herdr 0.9.5): with OMP. Known limit: if the connection stalls, a Terminal request already sent can still move the desktop after you pick another tab; the view you picked does not change.
- Chat: Send to Claude Code stays blocked with Herdr 0.9.5. Herdr 0.9.5 drops the true inverse cell style that Claude draws its input caret with; the hidden cursor position is still there, but Herdline needs that style to confirm Claude is at its prompt. A successful Send needs an upstream Herdr fix, and such a fix would still need testing. The input-box refusal messages no longer name a specific program. Partly device-verified (QA, emulator, stock Herdr 0.9.5): Send is refused with Claude Code, nothing is sent, and the refusal names no program. A successful Send is not verified.
- Chat: the "Opening Terminal" and "Couldn't open Terminal" messages name the tab as the header shows it. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Chat: Terminal from Chat now also waits for the terminal picture to show the pane before it switches. It switches at once only when the desktop and its picture are both on that pane already. If the desktop is on the pane but the picture lags, it waits without asking the desktop to move. If the connection is not live, it says it couldn't open Terminal and offers Try again, without asking the desktop to move. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Chat: Terminal from Chat now opens the pane you are reading. If the desktop is on another pane, the app moves it to that pane once; it shows "Opening Terminal for …" and stays in Chat until Terminal is showing that pane. If it can't, it says it couldn't open Terminal for that pane, keeps you reading it in Chat, and offers Try again. Device-verified (QA, emulator, stock Herdr 0.9.5).
- Tabs: the view button in the Tabs header now cycles List, Two columns and Workspace rails. Under the host, a second line shows the tab and workspace counts; a long host name is shortened first, before the counts. Partly device-verified (QA, emulator, stock Herdr 0.9.5): the view button's cycle.
- Chat: the pane you select stays in Chat and shows its own loading, history or read-error state. A page read successfully with no entries shows as empty. A history that is not written yet stays a read error with Retry, and recovers through the usual polling. An agent that refuses shows its refusal text with Open Terminal. Chat no longer falls back to Terminal on its own; Terminal opens only when you choose it. The old notice saying Chat can't read this agent, so this tab shows Terminal, is removed. Partly device-verified (QA, emulator, stock Herdr 0.9.5), with OMP and Claude Code: a selected pane whose history is not written yet stays in Chat with the read error, Retry and Open Terminal, then shows its history through polling. The empty page and the refusal state are code and unit tested only. That this fixes the reported incident is inferred, not proven on a device.
- Agents: the Agents screen uses a compact header, without the large empty space above the title. Code and unit tested only, not device-verified.
- Chat: a steer typed into a working OMP pane says it waits in OMP and is marked delivered once OMP's history holds it. Code and unit tested only, not device-verified.
- Tabs: the Tabs sheet has one header in List, Two columns and Workspace rails, with New tab always on its own row at the right, above Search. Code and unit tested only, not device-verified.
- Chat: dragging the Chat list by hand hides the keyboard once; the draft is kept. Code and unit tested only, not device-verified.
- Tabs: Settings › Layout › Tabs view offers Workspace rails: workspaces scroll down, and each workspace's tabs sit in one row that scrolls sideways. List stays the default. Code and unit tested only, not device-verified.

Device-verified means checked by QA on an Android emulator with stock Herdr 0.9.5, using OMP, Claude Code and Kilo with a test model provider, on this build or an earlier one, carried forward only where the code path is unchanged. No line claims more on a device than QA proved. Lines not marked device-verified are code and unit tested, except the parts marked code only, which are not unit tested.

This is an experimental build, and support for agent harnesses is not complete.

Known limits:
- The composer's same-name case was run only with two same-named tabs in one workspace, with OMP; same-named tabs in different workspaces were not run on a device.
- Nothing is verified on a phone, including a stock Samsung phone.
- A desktop focus request already sent can still land after you pick another tab; the view you picked stays.
- This release makes no promise of automatic reconnect.
